# Relay 托管页面 AI 生成规则

以下约束仅适用于本次要交给 Relay「页面托管」的网页及其发布产物。结合我的具体需求使用，不改变项目原有规则、安全与授权边界，也不用于约束其他任务。

- 保留已有源码和目录组织；不要为满足托管要求改写 `AGENTS.md`、`WORKBUDDY.md` 等规则文件、删除项目文件或重构整个项目。
- 简单页面直接生成静态文件；已有项目沿用现有技术栈，在独立产物目录整理可托管文件。无需为托管额外引入框架、依赖或任务管理流程。无法满足的需求应说明限制，不擅自扩大改动。

## 交付方式

- 简单页面优先交付一个 UTF-8 编码的 `index.html`，可内联 CSS、JS；有配套资源时交付静态目录，需通过浏览器上传时打包成 ZIP，无需强制同时交付两份。推荐结构为 `index.html` 与 `assets/`，ZIP 根目录直接放首页和资源。
- 需要编译的项目沿用现有构建方式，交付构建后的静态产物（如 `dist`），本次构建使用相对资源基址；必要调整仅针对托管产物，避免影响其他发布方式。Relay 不安装依赖、不构建、不运行后端；服务端渲染项目须静态导出，不能只打包源码。
- 上传入口只接受 `.html`、`.htm`、`.zip`；服务器本机可导入这些文件或完整静态目录。单独上传 HTML 不会自动带上本地配套文件。

## 支持的文件与大小

目录及 ZIP 内当前允许下列扩展名（不区分大小写）；这是托管支持清单，不是所有静态网页格式的完整列表：

| 用途 | 扩展名 |
|---|---|
| 页面、样式、脚本 | html htm css js mjs |
| 数据与文本 | json map txt xml csv |
| 图片 | svg png jpg jpeg gif webp avif ico bmp |
| 字体 | woff woff2 ttf otf eot |
| 文档 | pdf |
| 音视频 | mp3 wav ogg mp4 webm m4a aac |
| 字幕 | vtt |
| 其他静态资源 | wasm webmanifest |

允许托管不代表设备一定能播放；音视频还受容器、编码及浏览器/设备支持影响，字幕使用 UTF-8 WebVTT。未列出的格式可按实际需求向管理员建议扩展，不要直接混入发布包。参考：[WebVTT](https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API)、[媒体格式与编码](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats)。

- 上传的 HTML 或 ZIP 最大 32 MiB；目录/ZIP 内每个文件最大 32 MiB；每站解压后最多 128 MiB、1500 个文件；全部站点总配额 1 GiB。
- 必须包含 HTML 首页，推荐根目录 `index.html`；多个 HTML 且无法自动确定首页时需手动选择。
- 发布产物只保留页面及所需资源，排除源码工程文件、依赖、配置、隐藏项和其他压缩包；不要因此删除源项目中的这些文件。
- 包内路径使用 `/`，不含绝对路径、空路径段、`.` 或 `..` 路径段；不用链接文件、以点开头的名称、Windows 非法/保留名称、以点或空格结尾的名称。避免重复或仅大小写不同的文件名，路径不超过 512 个字符，目录尽量扁平（本机目录导入最多递归 20 层）。目录导入虽会跳过隐藏项和 `node_modules` 等，其他不支持的文件仍会使导入失败。

## 资源与导航

- 本地资源和页面链接使用相对路径，例如 `./assets/style.css`、`./assets/app.js`、`./about.html`；CSS 的 `url()` 相对 CSS 文件定位。引用可用 `../` 指向站点内的上级目录，但不能越出站点。托管地址位于 `/p/<站点标识>/` 下，不要写死域名、站点标识、`/assets/...`、`file://` 或电脑绝对路径。
- 不使用 `<base>`。SPA 使用 hash 路由；托管没有将任意前端路由回退到首页的能力。
- `fetch('./data.json')` 相对当前 HTML 地址定位，不是相对外部 JS 文件；模块内资源可用 `new URL('./asset.png', import.meta.url)` 相对模块定位。动态引用和脚本拼接路径不会自动修正；静态引用也不应依赖导入修正。文本使用 UTF-8。
- HTML 不因内嵌资源较大而整页跳过路径检查；CSS 与模块脚本在每个文件内分别采用累计 2 MiB 解析预算，内嵌代码与样式属性也计入。超过剩余预算的部分保留原样并提示，独立 CSS／JS 文件同样受限；生成时仍应直接使用正确的相对路径。
- 优先随包提供资源；远程资源使用 HTTPS 并说明联网依赖。沙箱使用不透明源，数据、模块、字体等跨源请求需满足对应 CORS 要求，可能携带 `Origin: null`；不要依赖携带登录凭证的请求。托管资源提供允许匿名跨域读取的响应头，最终以托管预览为准。

## 浏览器运行边界

- 页面可执行脚本、下载文件；不能依赖 Relay 登录态、Cookie、localStorage/sessionStorage、IndexedDB 等同源持久存储。需要保存用户数据时可提供显式导出/导入，避免刷新后丢失却声称已永久保存。
- 不依赖 Service Worker、Web Worker、原生表单提交或弹出新窗口；可在页面内处理输入。`object/embed` 被禁用，PDF 可作为下载链接；托管页自身也不能被 iframe 嵌入。
- 托管接口只提供静态文件读取，不提供业务后端或 Relay 内部 API 权限。外部 API 须兼容上述跨域限制，且不能要求在公开页面中暴露秘密凭证。

## 验证与交付

- 验证沿用项目已有约定，只补充与页面有关的资源、交互及适用的移动布局/下载检查。说明交付路径、首页、外部依赖和实际验证结果；本规则不另行要求报告或测试体系，没有环境验证时如实说明。
- 管理员可在「页面托管」导入、检查并预览，确认后发布；双击 HTML 的效果不能代替托管沙箱验证。本机导入是副本，源文件改动后需重新导入；更新已有站点保留访问链接。
- 页面和全部资源发布后均可被持链接的人访问，不能放入密钥、令牌或私密内容。生成文件不等于授权上传或公开发布，按当前任务已有授权执行，不重复询问已明确授权的动作。
